# Gatekeeper · AI 开发流程管理工具

把「AI Agent 作为独立开发角色参与编程」从口头约定变成**可执行、可审计、可回流的流程**。
本仓库包含设计文档、流程管控台（Gatekeeper Web 应用）与自检测试套件。

## 它能干什么

Gatekeeper 把一次开发任务组织为 **G0–G10 十一个阶段的门禁流水线**，三类主体各司其职：

| 主体 | 能做 | 不能做 |
| --- | --- | --- |
| **AI Agent** | 加载上下文、写 PRD / Plan / Task、按 TDD 写测试与实现、提交产出 | 审批、签字、跳过门禁 |
| **工具链（CI）** | 跑测试 / Lint / 覆盖率 / 越界检测，签名回传证据（绑定 commit / diff hash） | 采信 AI 自报、替人批准 |
| **人** | 批准门禁、打回、逐 Task Review、熔断裁决、记忆确认、精简跳过 | ——（唯一审批主体） |

核心能力：

- **门禁制流程**：每个阶段「AI 产出 → 机器验证 → 人签署」三步走，未过门禁不进入下一阶段；AI 的「已自测全绿」属于自报声明，只有工具链签名并绑定 hash 的证据才解锁门禁。
- **逐 Task 实现循环（G4）**：Task 带显式依赖关系（图形化 DAG 展示），红 → 绿 → 越界检测 → 人独立 Review，失败熔断待人裁决。
- **全程留痕可审计**：每步自动执行生成完整凭证（gk.receipt/1：主体 / 时间 / 输入 / 输出 / 关联），不可变事件日志 + 工件 / 证据 / 文件随时回查。
- **项目记忆回流（G10）**：人的每次打回意见、越界说明、方案调整都会提炼为候选记忆，人确认后注入下一轮 G0——同一个错误不会犯第二次。
- **精简流程**：普通任务（如普通改代码）可经人确认跳过个别阶段（如 G9 运维），留痕但不影响门禁口径。
- **内容外置、插件化存储**：流程状态里只存 `{uri, hash, sizeBytes}` 引用，文档 / 产物 / 证据 / 凭证本体经 GKSTORE 插件写入外部（虚拟仓 / 本地目录 / 未来 Git 仓库等），升级存储只需换插件。

## 价值

1. **可信**：人只做一次判断，其余自动执行；但每个自动步骤都有凭证、签名与 hash 可回溯。
2. **高效**：正常流转「批准即放行」，系统自动编排 TDD 循环；异常（打回 / 熔断 / 中断）才需要人介入。
3. **不丢经验**：教训固化为项目记忆并强制回流，团队经验不随人员流失。
4. **可演进**：AI / 工具链目前是模拟适配器，接入真实模型 / 真实 CI 只需替换适配器，接口与状态机不变（见接口规范）。

## 部署

三种方式（详见 [部署.md](部署.md)）：

- **直接打开**：双击 `gatekeeper/index.html`（零依赖，个人试用）。
- **本地静态服务（推荐）**：双击 `serve.cmd`（Windows），或任意平台 `npx -y http-server gatekeeper -p 8931 -a 127.0.0.1 -c-1 -o`，打开 `http://127.0.0.1:8931/`。
- **GitHub Pages**：仓库 Settings → Pages → 分支 `master` / 目录 root，访问 `https://volcanochen.github.io/ai-dev-mgr/gatekeeper/`。

发布门禁：部署前必须 `node selftest.js` 全过（561 断言，含接口规范测试套件）。

## 使用

1. **新建任务**：总览页输入任务名 →「新建并进入流程」，任务即成为独立 G0–G10 实例并自动启动 G0。
2. **人只看一个页面**：「审批台」——先读执行授权单（本阶段 AI 要做什么、按什么标准算通过），再批准 / 打回 / 跳过；G4 有快捷入口直达循环 Review 页，G10 直达记忆确认页。
3. **自动执行回看**：批准后系统自动跑完 AI 与工具链动作，过程默认收起，需要时展开或去「执行追溯」看每步凭证。
4. **数据管理**：顶栏「导出 / 导入」备份流程数据；「内容存储」切换外部存储插件（虚拟仓 ↔ 本地任务目录）。
5. **多任务**：总览页管理多个并行任务，支持搜索 / 归档 / 派生子任务（下一轮复盘驱动的重做）。
